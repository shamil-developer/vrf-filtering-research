# Исследование фильтрации трафика в VRF-контурах

Исследовательский стенд для проверки и сравнения подходов к фильтрации сетевого трафика в VRF-контурах. Репозиторий содержит воспроизводимую среду для функционального тестирования, нагрузочных испытаний и подготовки архитектурных решений.

Цель репозитория:
- Проверить, как `nftables` правила применяются к интерфейсам типа `vrf` и `bridge`
- Замерить деградацию производительности (`iperf3` или иной инструмент) при наличии 1000+ правил
- Исслудовать выбор между `nftables` и гибридом `tc+eBPF`


## Запуск стенда

Стенд нужно запускать в Docker-контейнере. Внутри контейнера программа создаёт Linux namespaces, bridge, VRF, veth-интерфейсы и маршруты.

Обычный запуск nft benchmark:

```bash
make lab
```

Она собирает Go-образ, используя Docker cache, запускает контейнер в foreground, выполняет Go-приложение по `lab.yaml` и закрывает контейнер после завершения программы.

Полное сравнение nft и гибрида tc+eBPF:

```bash
make full-compare
```

Эта команда последовательно запускает три контейнера:

- `nft` benchmark в чистом контейнере;
- `tc+eBPF` benchmark в новом чистом контейнере: простые правила вешаются через `tc flower`, сложные уходят в eBPF classifier;
- compare-запуск, который читает JSON-отчеты и выводит сравнение.

Отдельные команды:

```bash
make bench-nft
make bench-tc-ebpf
make compare
```

`lab.yaml` создаёт сетевую карту и запускает benchmark-серию `iperf3`: baseline без правил, затем `100`, `200`, ... `1000` правил текущего engine.

Результаты benchmark сохраняются в:

```bash
reports/nft.json
reports/tc_ebpf.json
```

Compare читает эти файлы через `compare.yaml`.

## Проверка внутри контейнера

После `make docker-lab` можно проверить созданную карту:

```bash
ip netns list
ip -br link
ip route show table 100
```

Проверить связность:

```bash
ip netns exec ns-client ping -c 3 10.0.2.2
ip netns exec ns-server ping -c 3 10.0.1.2
```

Текущая адресация:

- `ns-client`: `10.0.1.2/24`
- VRF-side gateway для клиента: `10.0.1.1/24`
- VRF-side gateway для сервера: `10.0.2.1/24`
- `ns-server`: `10.0.2.2/24`

Все команды создания описаны в `lab.yaml`. Если нужно сбросить стенд, достаточно выйти из контейнера и запустить новый контейнер заново.
